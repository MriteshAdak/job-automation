## 1. Executive Summary & Component Scope

SF-05 delivers the complete Salesforce DX metadata, permission model, contract mapping, validation rules, and offline verification suite for generation requests. It establishes the durable, inspectable bridge between the candidate's tracking environment in Salesforce and the local document generation subsystem, strictly implementing Contract `C13` (`GenerationRequest` and `GenerationRequestObservation`).

### 1.1 Core Architectural Guarantees
1. **Decoupled Creation & Offline Worker Inspectability**:
   A candidate can create a generation request directly from standard Salesforce UI at any time—even while the local Windows worker process is entirely offline, suspended, or unauthenticated. The record persists durably with initial status `Pending` without throwing runtime errors or leaving broken references.
2. **Contract C13 Fidelity**:
   All 23 custom fields on `Generation_Request__c` map 1:1 to Contract `C13` domain properties, including immutable contract versioning (`Contract_Schema_Version__c = "1.0"`), optional external idempotency keys (`Client_Request_Key__c`), document generation parameters, frozen input snapshot hashes, and delivered artifact locators.
3. **Strict Privilege Separation (Least-Privilege RBAC)**:
   - **Candidate (`Job_Generation_Requester`)**: Read/Create on `Generation_Request__c`, Read on `Job__c`/`Company__c`. Can populate request parameters upon insert; **zero edit authority** over operational state, claim timestamps, frozen versions, or delivered artifacts; **zero delete authority**.
   - **Worker (`Job_Automation_Worker`)**: Read/Edit on `Generation_Request__c`, Read on `Job__c`/`Company__c`. Can update lifecycle status and diagnostic fields; **read-only** on candidate creation inputs; **strictly read-only** on candidate tracking fields (`Application_Progress__c`, `Candidate_Notes__c`) on `Job__c`; **zero create or delete authority**.
4. **Strict Separation of Processing vs. Approval Semantics**:
   Completion of document generation advances the request to `Ready_for_Review` and records the artifact references (`Result_Artifact_Ref__c` and `Local_Artifact_Ref__c`). This status **never** implies or automatically sets candidate document approval, nor does it advance the candidate's `Application_Progress__c` on the parent `Job__c`. Document review and approval remain strictly candidate-controlled under future story SF-07 (Contract `C14`).
5. **False-by-Default Unavailable Job Override & Preflight Failures**:
   `Allow_Unavailable_Job__c` defaults strictly to `false`. If a target job has an inactive or closed posting availability and this override is `false`, the worker transitions the request directly from `Pending` to `Failed` (`Error_Reason__c = "job_unavailable"`) without claiming the request or freezing versions.
6. **Safe Diagnostic Visibility**:
   Failures record sanitized diagnostic messages (`Error_Message__c`), machine-readable reason codes (`Error_Reason__c`), and correlation references (`Error_Ref__c`). Diagnostic messages are scrubbed of Windows host file system paths, credentials, and API tokens prior to persistence in Salesforce.
7. **Lineage & Parent Integrity**:
   Lookups to `Job__c` and `Predecessor_Request__c` enforce `deleteConstraint="Restrict"`. Deletion of a parent job is blocked by the platform while generation audit records exist, preventing orphaned records and cascade-deletion data loss.

### 3.1 Permission Set Comparison Matrix

| Permission Dimension | Candidate (`Job_Generation_Requester`) | Worker (`Job_Automation_Worker`) |
|---|---|---|
| `Generation_Request__c` Object | Read, Create (**No Edit**, **No Delete**) | Read, Edit (**No Create**, **No Delete**) |
| `Job__c` Object | Read (**No Delete**) | Read, Create, Edit (**No Delete**) |
| `Company__c` Object | Read (**No Delete**) | Read, Create, Edit (**No Delete**) |
| Candidate Creation Inputs (`Job__c`, `Document_Type__c`, etc.) | **Read-Write at insert**; Read-Only after insert | **Strictly Read-Only** |
| Worker Operational Fields (`Status__c`, `Worker_Claimed_At__c`, etc.) | **Strictly Read-Only** | **Read-Write** |
| Frozen Version Snapshots (`Frozen_*_Version__c`) | **Strictly Read-Only** | **Read-Write at claim**; Immutable thereafter |
| Error & Diagnostics (`Error_Reason__c`, `Error_Message__c`, etc.) | **Strictly Read-Only** | **Read-Write** |
| Delivered Artifacts (`Result_Artifact_Ref__c`, `Local_Artifact_Ref__c`) | **Strictly Read-Only** | **Read-Write** |
| Candidate Tracking Fields on `Job__c` (`Application_Progress__c`, etc.) | **Full Candidate Authority** | **Strictly Read-Only** |
| Administrative System Permissions | **None** | `ViewSetup` (for `/limits` read-only monitoring) |

## 4. Platform Validation Rules (13 Invariants)

| Validation Rule API Name | Enforced Condition | Error Message |
|---|---|---|
| `Job_Required` | `ISBLANK(Job__c)` | A generation request must reference a valid Job record. |
| `Template_Id_Required` | `ISBLANK(Template_Id__c)` | Template ID is required for document generation. |
| `No_Self_Predecessor` | `NOT(ISBLANK(Predecessor_Request__c)) && Predecessor_Request__c == Id` | A generation request cannot be its own predecessor. |
| `Client_Request_Key_Immutable` | `NOT(ISNEW()) && (ISCHANGED(Client_Request_Key__c) && (NOT(ISBLANK(PRIORVALUE(Client_Request_Key__c))) || NOT(ISBLANK(Client_Request_Key__c))))` | Client Request Key is immutable once created and cannot be added or modified on an existing record. |
| `Client_Request_Key_No_Whitespace` | `NOT(ISBLANK(Client_Request_Key__c)) && (CONTAINS(Client_Request_Key__c, ' ') || ...)` | Client Request Key must not contain whitespace characters. |
| `Immutable_Creation_Inputs` | `NOT(ISNEW()) && (ISCHANGED(Job__c) \|\| ISCHANGED(Document_Type__c) \|\| ...)` | Generation request creation inputs (Job, Document Type, Language, Template, Strategy, Availability Override, Predecessor) are immutable after creation. |
| `Claim_Requires_Claimed_At_And_Versions` | `(Running \|\| Upload_Pending \|\| Ready_for_Review) && (ISBLANK(Worker_Claimed_At__c) \|\| ISBLANK(Frozen_Posting_Revision__c) \|\| ...)` | Claimed and active generation requests must specify Worker Claimed At and all frozen input snapshot versions. |
| `Frozen_Versions_Immutable` | `NOT(ISNEW()) && (PRIORVALUE(Frozen_Posting_Revision__c) != null && ISCHANGED(Frozen_Posting_Revision__c) \|\| ...)` | Frozen input versions cannot be modified once set. |
| `Claimed_At_Not_Before_Created` | `Worker_Claimed_At__c < CreatedDate` | Worker Claimed At timestamp cannot be earlier than record creation time. |
| `Completed_At_Not_Before_Created` | `Completed_At__c < CreatedDate` | Completed At timestamp cannot be earlier than record creation time. |
| `Completed_At_Not_Before_Claimed` | `NOT(ISBLANK(Worker_Claimed_At__c)) && Completed_At__c < Worker_Claimed_At__c` | Completed At timestamp cannot be earlier than Worker Claimed At timestamp. |
| `Ready_Requires_Completion_And_Result` | `Ready_for_Review && (ISBLANK(Completed_At__c) \|\| ISBLANK(Result_Artifact_Ref__c))` | Generation request in Ready for Review status must specify Completed At and a Result Artifact Reference. |
| `Failed_Requires_Completion_And_Error` | `Failed && (ISBLANK(Completed_At__c) \|\| ISBLANK(Error_Reason__c))` | Failed generation request must specify Completed At timestamp and an Error Reason. |

## 6. Downstream Integration Requirements

SF-05 establishes the foundational data contract for several subsequent stories across Phases 1 and 2:

### 6.1 SF-06: Generation Actions & Flows
- **UI Quick Action**: SF-06 will introduce Lightning Quick Actions (or Screen Flows) on the `Job__c` layout to allow 1-click creation of `Generation_Request__c` records with pre-populated `Job__c`, `Document_Type__c`, and `Language__c`.
- **Flow Invariants**: Must respect `Immutable_Creation_Inputs` and ensure `Allow_Unavailable_Job__c` defaults to `false`.

### 6.2 GEN-01: Ingestion & Admission
- **Polling Query**: Uses `RequestFieldMapping.build_soql_query()` to discover `Pending` records.
- **Deterministic Identity**: Local `request_id` derived via UUIDv5 from `(org_id, canonical_salesforce_id)`.
- **Preflight Check**: Evaluates target job availability. Closed/unavailable jobs fail immediately without worker claim.

### 6.3 GEN-02: Orchestration & Claiming
- **Claim Transition**: Transitions state from `Pending` $\rightarrow$ `Running`, setting `Worker_Claimed_At__c = now()` and recording `Frozen_Posting_Revision__c`, `Frozen_Profile_Version__c`, `Frozen_Policy_Version__c`, and `Frozen_Template_Version__c`.
- **Result Projection**: Upon successful generation, sets `Status__c = "Ready_for_Review"`, `Completed_At__c = now()`, `Result_Artifact_Ref__c = <ContentVersionId>`, and `Local_Artifact_Ref__c = <bundle_id>`.

### 6.4 SF-07: Document Storage & Candidate Approval
- **Contract C14 Integration**: Delivers the generated PDF/DOCX to Salesforce Files (`ContentVersion`).
- **Separate Approval Lifecycle**: Candidate uses a dedicated approval UI to transition documents between `draft`, `approved`, and `superseded`.
- **Application Progress Independence**: Request status `Ready_for_Review` delivers artifacts for candidate inspection, but leaves candidate `Application_Progress__c` strictly under candidate control.
