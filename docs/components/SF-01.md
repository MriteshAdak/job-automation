## 1. Executive Summary & Component Scope

SF-01 implements the version-controlled, scoped Salesforce metadata and explicit application mappings required to synchronize evaluated job vacancies into the user's existing Salesforce Developer Edition org (`dev-main`).

### 1.1 Core Deliverables & Accomplishments
1. **Scoped, Versioned Salesforce Source Format Metadata (`salesforce/`)**:
   - Authored complete Salesforce DX source format structure rooted in `salesforce/` with `sfdx-project.json`.
   - Defined `Company__c` and `Job__c` custom objects with standard labels, descriptions, and private sharing models.
   - Defined unique canonical External ID fields (`Canonical_Company_Id__c` and `Canonical_Job_Id__c`) with case-insensitive uniqueness and UUID validation/immutability rules.
   - Defined all machine-owned fields, parent-child lookup relationship (`deleteConstraint="Restrict"`), and picklist value sets.
   - Defined candidate-owned tracking fields with creation default `Application_Progress__c = 'New'` and blank initial values for notes, decisions, and dates.
   - Packaged strictly scoped manifests: `salesforce/manifest/package.xml` and `salesforce/manifest/sf01.xml` (excluding wildcards and standard profiles).
2. **Metadata Compatibility & Schema Parser (`metadata_parser.py`)**:
   - Implemented an XML parser and schema validator that checks Salesforce DX metadata against `SyncMappingConfig`.
   - Verifies field existence, data types, external ID flags, case sensitivity, lookup reference targets, delete constraints, picklist values, defaults, nullability, and validation rules.
3. **Collision & Ownership Hardening (`sync_settings.py`)**:
   - Enhanced `SyncMappingConfig._validate_ownership_separation` to catch intra-entity machine role aliasing, candidate field aliasing of external IDs or lookup keys, and object name collisions.
   - Added designated org-dependent TODO comments in `configuration.py` and `sync_settings.py`.
4. **Comprehensive Test Suite & Validation**:
   - Added `tests/salesforce/metadata/test_metadata_validation.py` (11 unit/compatibility tests).
   - Added `tests/salesforce/metadata/test_sf01_scenarios.py` (14 validation matrix scenario tests for V01–V18).
   - Verified 46 / 46 SF-01 relevant tests and 142 / 142 salesforce package tests passing cleanly on native Windows.
5. **Accurate Live Deployment Status**:
   - In strict adherence to blueprint §5 and repository instructions, **no live metadata deployment, deployment validation, or record mutation was performed**. Live deployment remains pending user confirmation of target org binding and SF-02 credential provisioning.

## 3. Metadata Changes and Physical Schema Specification

### 3.1 Custom Objects Created (`salesforce/force-app/main/default/objects/`)

#### 1. `Company__c` (`Company__c.object-meta.xml`)
- **Label**: `Company` | **Plural Label**: `Companies`
- **Sharing Model**: `ReadWrite` | **External Sharing Model**: `Private`
- **Standard Name Field**: `Name` (Text 80/255)
- **Description**: Stores employer companies associated with tracked job vacancies for personal job automation.

#### 2. `Job__c` (`Job__c.object-meta.xml`)
- **Label**: `Job` | **Plural Label**: `Jobs`
- **Sharing Model**: `ReadWrite` | **External Sharing Model**: `Private`
- **Standard Name Field**: `Name` (Text 80/255, labeled "Job Title")
- **Description**: Tracks evaluated job vacancies, relevance assessment, and candidate application progress.

### 3.3 Validation Rules Created

1. **`Company__c.Canonical_Company_Id_Format`**:
   - `errorConditionFormula`: `NOT(REGEX(Canonical_Company_Id__c, "^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$"))`
   - `errorMessage`: Canonical Company ID must be a valid 36-character lowercase hyphenated UUID.
2. **`Company__c.Canonical_Company_Id_Immutable`**:
   - `errorConditionFormula`: `AND(NOT(ISNEW()), ISCHANGED(Canonical_Company_Id__c), NOT(ISBLANK(PRIORVALUE(Canonical_Company_Id__c))))`
   - `errorMessage`: Canonical Company ID is permanent and cannot be modified once set.
3. **`Job__c.Canonical_Job_Id_Format`**:
   - `errorConditionFormula`: `NOT(REGEX(Canonical_Job_Id__c, "^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$"))`
   - `errorMessage`: Canonical Job ID must be a valid 36-character lowercase hyphenated UUID.
4. **`Job__c.Canonical_Job_Id_Immutable`**:
   - `errorConditionFormula`: `AND(NOT(ISNEW()), ISCHANGED(Canonical_Job_Id__c), NOT(ISBLANK(PRIORVALUE(Canonical_Job_Id__c))))`
   - `errorMessage`: Canonical Job ID is permanent and cannot be modified once set.

## 4. Contract and Application Mappings

### 4.1 Relationship to Shared Contracts
- **C07 `CanonicalJob` / `PostingRevision` (FND-01)**:
  - Canonical job UUID maps directly to `Canonical_Job_Id__c`.
  - Canonical company UUID maps to `Canonical_Company_Id__c`.
  - Salesforce record IDs (`Id`) and local remote entity mappings (`RemoteEntityMapping`) remain strictly separated from canonical UUIDs.
- **C11 `Assessment` (FND-01)**:
  - `final_disposition` maps via `disposition_mapping` (`eligible` -> `Eligible`, `review` -> `Review`, `rejected` -> `Rejected`).
  - `summary_reason` maps to `Assessment_Reasons__c`.
  - `relevance_score` and `score_scale` map to `Relevance_Score__c` and `Score_Scale__c` with explicit `None` clearing on rules-only re-evaluation.
- **C12 `SyncPayload` / `SyncOperation` (FND-01 / SYNC-01)**:
  - Outbound payloads serialize strictly machine-owned fields.
  - `assert_no_candidate_fields` guarantees that `Application_Progress__c`, `Candidate_Notes__c`, `Candidate_Decision__c`, `Follow_Up_Date__c`, and `Interview_Date__c` are excluded from all outbound JSON bodies.

### 4.2 Application Configuration Examples
- `config/sync.example.json`: Standard baseline mapping (`Company__c`, `Job__c`, standard `Name` fields).
- `config/sync.autonumber.example.json`: Autonumber fallback mapping (`title_field: "Job_Title__c"`, `company_name_field: "Company_Name__c"`).
- `config/sync.prefixed.example.json`: Prefixed collision avoidance mapping (`company_object: "JA_Company__c"`, `job_object: "JA_Job__c"`).
